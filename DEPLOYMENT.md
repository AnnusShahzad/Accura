# Deploying Accura on Render's free tier

This guide puts Accura online for free, entirely on **Render**, as a
**public demo**: sign-up is closed, visitors try it with one-click **guest
accounts** that are permanently deleted after 24 hours, and you keep an
admin account.

Everything runs as **one web service**: a single Docker image
([`Dockerfile`](Dockerfile)) runs the Next.js frontend on the public port
and the API next to it inside the same container. The browser only ever
talks to one URL. There is no API address to configure and no CORS, and
there is only one sleeping instance to wake. Data lives in Render's free
PostgreSQL.

> **Why not Vercel?** Answers are generated in background tasks that
> keep running after the request returns. Serverless functions (Vercel's
> model) stop as soon as the response is sent, so the API can't run
> there. Running the frontend on Vercel as well would split the app
> across two platforms for no benefit.

You need: a GitHub account with this repository, a free Render account,
and an API key for at least one AI provider (see [AI provider](#ai-provider)).

---

## Deploy

1. Push this repository to GitHub.
2. In Render: **New → Blueprint**, then select the repository. Render reads
   [`render.yaml`](render.yaml) and proposes the `accura` web service and
   the `accura-db` database.
3. Fill in the prompted values:

   | Variable | Value |
   |:--|:--|
   | `ADMIN_EMAIL`, `ADMIN_PASSWORD` | Your admin login. The password needs 9+ characters with upper, lower, number and symbol. |
   | `OPENAI_API_KEY` | Your key, or leave it empty and configure another provider afterwards (below). |

   Secrets (`JWT_SECRET`, `ENCRYPTION_KEY`) are generated by Render, and the
   database connection is wired in automatically.
4. **Apply**. The first build takes several minutes, because it builds the
   frontend and installs the API in one image. Then open the service's URL,
   e.g. `https://accura.onrender.com`.

That's it. Later pushes to the branch redeploy automatically.

## AI provider

Accura talks to every provider through the OpenAI-compatible API. Set
**one** of these in the service's **Environment** tab:

**OpenAI**
```
OPENAI_API_KEY=sk-...
```

**Any OpenAI-compatible endpoint** (OpenRouter, Groq, Together, a
self-hosted vLLM, ...). For example, OpenRouter with a free model:
```
DEFAULT_AI_PROVIDER=custom
CUSTOM_AI_BASE_URL=https://openrouter.ai/api/v1
CUSTOM_AI_API_KEY=sk-or-...
DEFAULT_GENERATOR_MODEL=openai/gpt-oss-20b:free
DEFAULT_EVALUATOR_MODEL=openai/gpt-oss-20b:free
```
Model ids are provider-specific, so check the provider's model list.
Free models are rate-limited and may be slow.

DeepSeek, Anthropic and Google work the same way via `DEEPSEEK_API_KEY`,
`ANTHROPIC_API_KEY` and `GOOGLE_AI_API_KEY`.

The app only offers models for providers that have a key, and new chats
default to `DEFAULT_GENERATOR_MODEL`. Users can also add their own keys
under **Settings → API Keys**.

## Guest accounts

- **Fresh every time.** Each "Continue as guest" creates a brand-new
  account with a random name. No email, name or password is asked for.
- **Deleted, not reset.** `GUEST_TTL_HOURS` (default 24) after it was
  created, the account stops working and is then **permanently deleted**,
  together with its chats, messages, saved API keys, settings and
  notifications. The cleanup runs every 5 minutes while the server is
  awake. Expired sessions are refused immediately either way.
- **What is stored meanwhile.** What a guest types is kept until deletion
  and is sent to your AI provider, whose own retention policy applies. The
  visitor's IP address is held in memory only, for the sign-up limits
  below, and is never written to the database.
- **Your key, your budget.** Guests use **your** AI key and are capped:
  `GUEST_REQUESTS_PER_DAY` (30 per guest), `GUEST_REQUESTS_PER_MINUTE` (5),
  `GUEST_MAX_ITERATIONS` (3 refinement rounds), at most 5 new guest
  sessions per IP per hour, and `GUEST_SIGNUPS_PER_HOUR` (60) for the
  whole site.

## Database

`render.yaml` creates a free Render PostgreSQL database and passes it in as
`DATABASE_URL`. Render's free databases expire after a limited period (30
days at the time of writing) and must then be upgraded or recreated. Tables
are created on start, so a new database just starts empty. Guests are
temporary anyway, and the admin account is recreated from `ADMIN_EMAIL` /
`ADMIN_PASSWORD`.

If you'd rather keep data indefinitely, point `DATABASE_URL` at any other
PostgreSQL. A free [Neon](https://neon.tech) database works; keep its
`?sslmode=require`.

No migration step is ever needed: new columns are added automatically on
upgrade.

## What to expect on the free tier

- **Sleeping.** The service stops after about 15 idle minutes, and the next
  visit waits roughly a minute while it starts. If the page loads before the
  API is ready, it shows "Starting the server…" and continues on its own.
- **Restarts.** A deploy or restart interrupts answers that are still being
  generated. Those chats show "The server restarted before this response
  finished" with a **Retry** button.
- **Memory.** Both processes together stayed under 150 MB of the
  512 MB instance in testing.
- **Email** isn't needed, since registration is closed. Without SMTP,
  password-reset emails can't be sent. To reset the admin password, change
  `ADMIN_PASSWORD` and restart.
- **Billing** runs in demo mode (no charges) unless you add Stripe keys.
  Guests can't change plans.

## Settings reference (public demo)

| Variable | Demo value | Meaning |
|:--|:--|:--|
| `REGISTRATION_ENABLED` | `false` | Self-service sign-up |
| `GUEST_ENABLED` | `true` | "Continue as guest" |
| `GUEST_TTL_HOURS` | `24` | Guest lifetime before permanent deletion |
| `GUEST_SIGNUPS_PER_HOUR` | `60` | New guest sessions per hour, site-wide |
| `ALLOW_PRIVATE_URLS` | `false` | Forbid MCP / custom-endpoint / webhook URLs on private networks (SSRF protection). Keep `false` when strangers can sign in. |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | yours | Admin created or updated on every start |
| `JWT_SECRET`, `ENCRYPTION_KEY` | generated | Any long random strings. Don't change `ENCRYPTION_KEY` later, or stored API keys can't be decrypted. |

All other settings are listed in [`backend/.env.example`](backend/.env.example).
Admins can also override most settings at runtime under
**Admin → Configuration**.

## After deploying

1. `https://<your-service>.onrender.com/api/v1/health` returns
   `{"status": "healthy", ...}`.
2. `https://<your-service>.onrender.com/api/v1/public/config` shows
   `"registration_enabled": false`, guests enabled, and your provider under
   `available_providers`.
3. On the site, **Continue as guest** and send a prompt. You should get a
   scored answer.
4. Log out, sign in with `ADMIN_EMAIL`, and open **Admin**.

## Troubleshooting

| Symptom | Fix |
|:--|:--|
| Every chat fails with "No API key configured for provider …" | Configure a provider (see [AI provider](#ai-provider)). With a custom endpoint, also set `DEFAULT_AI_PROVIDER=custom`. |
| Models show "needs API key" | That provider has no key on the server. Add one, or use the defaults. |
| Deploy fails with "Insecure configuration" in the logs | `JWT_SECRET` or `ENCRYPTION_KEY` is missing. The Blueprint generates both; set them by hand if you created the service manually. |
| Admin can't log in | `ADMIN_PASSWORD` must meet the password policy. Check the logs for "ADMIN_PASSWORD rejected". |
| "Guest access is very busy right now" | `GUEST_SIGNUPS_PER_HOUR` was reached. Raise it if your AI budget allows. |

## Running the same image elsewhere

The image is not tied to Render. Any container host that sets `PORT` works:

```bash
docker build -t accura .
docker run -p 10000:10000 --env-file backend/.env -e DATABASE_URL=postgres://... accura
```
